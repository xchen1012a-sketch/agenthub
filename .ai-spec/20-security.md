# 安全边界（`20-security.md`）

> `BND-1`–`BND-4` 已覆盖最顶层的四条红线。本文件写**这些红线的落地约束**与其余安全边界。
> 本文件全部规则至少 ✅ MUST；标记 📌 SHOULD 的可按 `_index.md` §2 偏离。

---

## SEC-1 脱敏必须按字段名判定（✅ MUST）

**禁止**用正则表达式做凭证脱敏。

**必须**用"字段名黑名单 + 白名单"双过滤：命中黑名单**必须**整体替换为 `***`；不在白名单的字段**必须**丢弃（默认拒绝）。

**为什么**：正则可被编码、嵌套、分片绕过；字段名匹配是确定性判定。

---

## SEC-2 凭证只在最短路径内以明文存在（✅ MUST）

外部凭证**必须**加密落库，运行时**必须**仅在"工具执行前 → 发出请求"这段最短路径内解密。

**禁止**：把解密的明文写入任何日志、事件、审计字段或返回体；执行完成后**禁止**继续持有明文引用。

**为什么**：明文存活时间越长、经过的组件越多，泄漏面越大。

---

## SEC-3 外部系统权限失败必须阻断（✅ MUST）

外部系统返回权限类失败（如 403）时**必须**阻断本次调用，并记录为拒绝。

**禁止**把它当作可重试或可忽略的错误继续执行。

**为什么**：权限失败往往意味着凭证越权或配置错误，继续执行会把错误放大。

---

## SEC-4 Cookie 与会话（✅ MUST）

会话 Cookie **必须**同时满足：`httpOnly`、`sameSite=lax`、`path=/`、有明确过期时间；生产环境**必须**启用 `secure`。

**禁止**把用户身份放在 Cookie 之外可由客户端自由指定的位置。

**为什么**：这些属性是防 XSS 与基础 CSRF 的最低要求。

---

## SEC-5 写接口必须防 CSRF（✅ MUST）

所有 `POST` / `PUT` / `PATCH` / `DELETE` 接口**必须**校验 CSRF 令牌。

**禁止**只依赖 `sameSite` 作为唯一防线。

**为什么**：`sameSite` 是浏览器行为，不是服务端校验。

---

## SEC-6 第三方插件需要allowlist 审查（✅ MUST）

**禁止**直接安装并授予凭证访问权的第三方插件。

**必须**先经过 allowlist 审查；未被审查的第三方插件不得进入 AgentHub profile。

**为什么**：插件运行在同一进程内，等于完全信任，不能默认放行。

---

## SEC-7 主密钥（✅ MUST）

主密钥**必须**只从环境变量注入，**禁止**进入仓库、镜像层、数据库或任何配置文件。

启动时**必须**校验其解码后长度等于 32 字节；不满足即启动失败。

**必须**保证主密钥可以轮换：轮换期间新旧密钥都能解密，旧密文惰性重加密。

**为什么**：密钥一旦入库或进仓库，轮换就失去意义。

---

## SEC-8 运行时加固（✅ MUST）

- 进程**禁止**以 root 运行。
- **禁止**越过受控目录进行任意文件读写。
- 出站网络**禁止**被用作进入内网的通道。

**为什么**：这是进程被攻破后的最后一道限制。

---

## SEC-9 安全测试必须存在（✅ MUST）

以下四类安全测试**必须**在每次提交中存在并执行：

| 关注点 | 必须证明什么 |
| --- | --- |
| 审计参数脱敏 | 敏感字段落库后均为脱敏值 |
| 会话无凭证 | 会话事件中不出现 Token / Password / Secret |
| 项目隔离 | A 项目看不到 B 项目的任何资源 |
| Prompt 无凭证 | Prompt 中不出现主密钥与 Token 值 |

**禁止**只断言"函数被调用"这类实现细节；**必须**断言可观察结果。

**为什么**：这四类对应当前已知的四种泄漏路径，缺一类就等于一条路径无人看守。
