# AgentHub 规范总入口（`_index.md`）

> 本目录（`.ai-spec/`）是 AgentHub 的**唯一事实来源**。代码、配置、迁移文件是"机器执行的事实"；本目录只写**机器强制不了、但越线会出事的边界**。
> 本文件不属于任何规则层，它只管规范自身怎么用。

---

## 1. 这个目录只写什么

| 写 | 不写 |
| --- | --- |
| 禁止什么（红线） | 怎么做（步骤、示例、推荐写法、目录树） |
| 必须成立什么（不变量） | 事实清单（字段、默认值、事件表、变量表） |
| 越线要走什么流程 | 进度、状态、版本号、变更日志 |

**判定法**：能被门禁 / 编译器 / 运行时证明的，就写成门禁或留在代码里；**只有机器证明不了的判断，才写成本目录的规则。**

**每条规则都必须有稳定 ID**，格式 `<前缀>-<序号>`。文档间只引用 ID，**禁止引用章节号**（章节号会随结构变动而指错地方）。

| 前缀 | 文件 | 管什么 |
| --- | --- | --- |
| `SPEC-` | 本文件 | 规范自身怎么书写、怎么改（不约束产品代码） |
| `BND-` | `00-boundaries.md` | 绝对红线（碰了就是事故） |
| `ARCH-` | `10-architecture.md` | 架构不许越的线 |
| `SEC-` | `20-security.md` | 安全红线 |
| `DATA-` | `30-data.md` | 数据与迁移规则 |
| `EXT-` | `40-extension.md` | 扩展契约 |
| `UP-` | `50-upstream.md` | 上游对接与版本锚点 |
| `QA-` | `60-quality.md` | 交付门槛 |
| `PIT-` | `70-pitfalls.md` | 项目踩坑边界（准入最严：连续踩坑 ≥2 次才登记） |

**冲突裁决顺序**：`00` → `10` → `20` → `30` → `40` → `50` → `60` → `70`。数字小的优先。

**ID 只增不改**：规则被废弃时保留 ID 并标注「已废弃」，**不得回收复用**。

## 2. 规则分几级

| 标识 | 含义 | 可否自由裁量 |
| --- | --- | --- |
| ✅ **MUST** | 违反即视为缺陷 | 不可 |
| 📌 **SHOULD** | 有充分理由可偏离 | 可，但须在 PR 说明替代方案 |
| 💡 **MAY** | 实现者自选 | 可 |

未标级别的规则按 **📌 SHOULD** 处理。

---

## 3. 改动分几等、各要走什么流程

等级**由"碰了哪类规则 ID"决定**，与改动大小无关。

| 等级 | 触发条件 | 必须交的证据 | 谁批 |
| --- | --- | --- | --- |
| **L0** | 不碰任何规则 ID | 相关测试通过 + 文档链接检查通过 | 自己 |
| **L1** | 碰 📌 SHOULD 级规则 | PR 描述中说明替代方案 | 自己 |
| **L2** | 碰 ✅ MUST 级规则 | 架构师签字 + PR 标注「架构例外」+ §4 例外登记（含可执行回退条件） | 架构师 |
| **L3** | 碰 `SEC-*` 或 `UP-*` | L2 全部 + 安全测试证据 + 独立 review | 架构师 + 安全负责人 |

**本目录的所有规则同样是 `ARCH-*` 级的 MUST**：改规范本身就是 L2。

## 4. 例外登记

偏离 ✅ MUST 必须在**下方表格登记**。这是唯一允许出现在本目录的记录，因为「哪条红线被批准偏离、何时回退」本身是约束。

| ID | 被偏离规则 | 例外内容与范围 | 回退条件 | 状态 |
| --- | --- | --- | --- | --- |
| EX-U1-HEALTHZ | `EXT-1`（业务路由前缀 `/agenthub/*`） | 运维存活探针保留 `GET /healthz`，不纳入业务前缀 | 部署平台统一支持带业务前缀的探针，且全部部署配置同步更新 | 方案已确认；PR 仍需架构师签字 |
| EX-I18N-HTTP | `QA-4`（禁止放宽门禁达成"绿"） | `verify-client-ui-i18n` 的 `IMMUTABLE_LANGUAGE_TOKENS` 收录 `HTTP`：客户端 `readError` 的兜底文案是 `HTTP <状态码> <路径>`，属语言中立的协议状态行，不是产品文案；仅当服务端返回非 JSON 错误体时才会出现 | 该兜底文案改为经 locale 字典产出（届时 `HTTP` 移出白名单，无需本例外） | **待架构师签字**；回退条件已写明 |

> 例外登记只增不删。回退条件必须**可执行**——写清"满足什么条件就该恢复默认"。

## 5. 规范自身怎么改

- **SPEC-1（✅ MUST）**：本目录只写边界与编码规范，**不得写"怎么做"**。出现"建议""可以先""推荐做法"即视为缺陷。
- **SPEC-2（✅ MUST）**：本目录不得出现可由机器证明的事实（表字段、变量默认值、事件 payload、目录结构、进度、版本号、变更日志）。
- **SPEC-3（✅ MUST）**：文档间引用规范一律用规则 ID，不得引用章节号。
- **SPEC-4（✅ MUST）**：每条规则必须带 ID 与级别；ID 只增不改，废弃时保留 ID 并标注「已废弃」。
- **SPEC-5（✅ MUST）**：新增或删除规范文件，必须同步本文件 §1 的前缀表与裁决顺序。
- **SPEC-6（✅ MUST）**：变更历史以 git 提交为准；本目录**不维护版本号、不维护修订记录**。
- **SPEC-7（📌 SHOULD）**：每条规则可带一句"为什么"，用于防止后人误删；不得借这一句夹带做法引导。

## 6. 上游文档的阅读边界

上游 `deepseek-harness/docs/` 中，**只有下列为权威依据**：`architecture.md`、`cordis-primer.md`、`tool-execution-pipeline.md`、`subsystems/{approval,credentials,invariants,slots,testing,workspace}.md`、`glossary.md`、`capability-seams.md`、`defensive-patterns.md`、以及各 `*-catalog.md` 生成物。

其余上游文档是历史档案，**不得作为实现依据**。

上游自身的规则文件（`deepseek-harness/AGENTS.md`、`deepseek-harness/packages/AGENTS.md`）属上游所有，只读，不得修改；它们约束的是上游代码，不是 AgentHub 的规则来源。
