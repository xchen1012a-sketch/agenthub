# 交付门槛（`60-quality.md`）

> 本文件定义"什么叫做完"。**测试怎么写、放在哪、用什么工具不在此列。**
> 每条门槛都必须能给出**可观察的证据**；**禁止**用"函数被调用过"这类实现细节充当证据。

---

## QA-1 验收项（✅ MUST）

下列各项**必须**通过，缺一项即视为未完成：

| ID | 必须证明什么 | 证据形态 |
| --- | --- | --- |
| V1 | 单容器可启动，存活探针返回健康 | 探针真实响应 |
| V2 | 不存在第二套 Agent 平台依赖 | 全仓检索无结果 |
| V3 | Project 与工作空间一对一，且唯一性由数据库保证 | 约束存在 + 违反时写入失败 |
| V4 | 运行时只暴露当前 Project 的工具与记忆，A 项目检索不到 B 项目任何资源 | 跨项目断言 |
| V5 | 模型与日志无法读到 Token / 密码 / 密钥 | 脱敏断言 + 落库后复查 |
| V6 | 外部系统权限失败被阻断 | 阻断行为断言 |
| V7 | Session / Project / 记忆 / 审计各有唯一主键与唯一事实来源 | 约束存在 |
| V8 | 高风险工具走完审批链并可被审计 | 端到端链路断言 |
| V9 | 改动集中在 AgentHub 自有代码 | 差异占比统计 |

**为什么**：这些是"企业可控"的最小证明集——缺 V4 是泄漏，缺 V5 是泄密，缺 V8 是越权。

---

## QA-2 安全测试的存在性（✅ MUST）

`SEC-9` 的四类安全测试**必须**存在且被执行；**禁止**以"覆盖率数字"替代它们的实际存在。

**为什么**：覆盖率不能证明"这条泄漏路径被堵住了"，只能证明"这行代码被执行过"。

---

## QA-3 迁移幂等（✅ MUST）

交付时迁移状态**必须**为"待执行数为 0"。

**禁止**交付含未应用迁移的状态。

**为什么**：未应用的迁移意味着代码依赖的列/表在目标环境不存在，运行期才会暴露。

---

## QA-4 静态门禁（✅ MUST）

交付前下列必须全绿：类型检查、静态检查、跨文件重复代码检测、AgentHub 自有红线扫描、客户端文案硬编码检查。

**禁止**通过放宽规则、加豁免、跳过检查来达成"绿"。

**为什么**：放宽规则等于把门禁变成装饰；例外必须走 `_index.md` §4 并说明回退条件。

---

## QA-5 证据不得预填（✅ MUST）

**禁止**在未真实执行的情况下把验收项标记为通过。

未执行的项**必须**显式标注为"未实测"并说明原因。

**为什么**：本仓已发生过方案书预填"已完成"而实际未验证的情况；预填会让后续判断建立在虚假前提上。

---

## QA-6 降级必须显式且不扩大授权（📌 SHOULD）

允许为可用性做降级（如检索失败不阻断对话），但**必须**：记录告警、保持原有授权边界、**禁止**因降级而放宽任何 `BND-*` / `SEC-*` 约束。

**为什么**：降级路径是攻击面常见的盲区——"出错时就更宽松"是最危险的失败模式。
