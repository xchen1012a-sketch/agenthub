# 绝对红线（`00-boundaries.md`）

> 本文件的规则**全部是 ✅ MUST**，且**优先级最高**——与其它规范冲突时，以本文件为准。
> 越线不是"技术选择"，是事故。任何偏离只能走 `_index.md` §4 例外流程（架构师签字 + 登记 + 可执行回退条件）。

---

## BND-1（✅ MUST） 凭证永远不可见

**禁止**在任何下列位置出现明文 Token / Password / Secret / 主密钥：

- Session 事件（含 Agent Loop 上下文）
- Prompt / system prompt（发给模型的任何文本）
- 事件总线 `ctx.emit()` 的 payload
- 审计与审批记录的结果字段
- 项目记忆内容
- 日志 / `console.log` / stderr
- HTTP 请求与响应正文

**为什么**：这些位置都会被模型、日志系统或外部系统读到；一旦落进去，凭证等于泄露，且无法撤回。

---

## BND-2（✅ MUST） 身份与授权不由模型决定

**禁止**模型决定以下任何一项：

- 用户身份（`userId` 必须来自服务端登录态）
- 角色 / 权限（必须来自成员关系表）
- 是否使用、以及使用哪个外部凭证（必须由凭证服务按"用户 + 系统连接"唯一确定）
- 工具是否需要审批（必须基于数据库中的风险等级字段）

**为什么**：模型可能被诱导；让模型决定身份等于把权限交给不可信输入。

---

## BND-3（✅ MUST） 风险默认拒绝

**必须**在下列情形拒绝执行，不得放行、不得降级为"仅告警"：

- 工具未配置明确策略
- 缺少外部凭证
- 审批超时、审批人缺失、凭证过期

**为什么**：默认放行的失败模式是"静默越权"；默认拒绝的失败模式只是"功能不可用"，后者可恢复。

---

## BND-4（✅ MUST） Project 数据零跨项目

**禁止**任何跨 Project 的数据泄漏或写入。具体地：

- 任何查询、检索、列表**必须**带 Project 归属条件
- 任何**写操作（确认 / 修改 / 删除）必须在同一条语句内同时约束"记录 id + Project 归属"**，不得拆成"先查归属再改写"
- 归属解析不出结果时**不得猜测**：必须放弃该次操作，不得回退到"默认项目"或"最近项目"

**为什么**：跨项目泄漏与"改错项目的数据"都是不可逆事故；拆分式校验给调用方留下漏判空间。

---

## BND-5（✅ MUST） 单底座

**禁止**引入第二套 Agent 平台或任何等价的 Agent 运行时。

**禁止**让 AgentHub 依赖 DeepSeek Harness 之外的 Agent 框架来承载核心能力。

**为什么**：双底座会让身份、凭证、审批三条链出现两套实现，红线无法统一保证。

---

## BND-6（✅ MUST） 单数据源

**禁止**引入 DeepSeek Harness 与其配置之外的持久化组件（额外的关系库、文档库、缓存、独立向量库均不允许）。

**为什么**：多数据源会让"唯一事实来源"失效，Project 隔离与审计无法给出完整证据。

---

## BND-7（✅ MUST） AgentHub 功能一律是插件

**禁止**用非插件方式实现 AgentHub 业务能力。所有 AgentHub 能力**必须**以 `packages/agenthub/*` 下的 Cordis 插件包形式存在。

**为什么**：插件是唯一能保证"注册即生效、销毁即卸载"的形态；非插件方式会绕过生命周期与依赖声明。
