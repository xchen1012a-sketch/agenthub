# 数据与迁移边界（`30-data.md`）

> **本文件不写表结构、不写字段清单、不写索引参数**——那些的唯一事实来源是 `packages/agenthub/migrations/sql/`。
> 本文件只写"迁移必须满足什么"与"数据库能力上不许越什么"。

---

## DATA-1 迁移是表结构的唯一事实来源（✅ MUST）

**禁止**在规范、方案书或 README 中手写表字段清单作为权威。

**必须**以 `packages/agenthub/migrations/sql/` 下的迁移文件为唯一依据；其它文档只能引用迁移文件。

**为什么**：手抄的清单必然漂移——本仓已发生过（方案书写"某表尚未建迁移"，而迁移文件早已存在）。

---

## DATA-2 已应用的迁移不得改动（✅ MUST）

**禁止**编辑、重命名、删除任何**已被应用**的迁移文件。

**必须**新增一个前向迁移来表达变更；维度或类型无法原地修改时，用"新列 + 数据重算 + 切列"，或在确认无数据时"删列重建"。

**必须**为不可逆变更提供成对的反向段。

**为什么**：已应用的迁移是历史，改动它会让不同环境的数据库状态分叉且无从发现。

---

## DATA-3 迁移命名与排序（✅ MUST）

- 文件名**必须**为 `NNNN_<package>_<name>.sql`，编号递增且不得复用。
- 包间执行顺序**必须**按依赖方向：`migrations` → `auth` → `rbac` → `project` → `system-connector` → `credential-vault` → `openapi-ingest` → `project-tool-scope` → `project-memory` → `approval` → `audit`。
- 主键**必须**统一为 UUID（Session 持久化表是既定例外）。
- 时间戳列**必须**统一为 `TIMESTAMPTZ NOT NULL DEFAULT now()`。
- 枚举字段**必须**加 CHECK 约束。

**为什么**：编号复用与乱序会让回放结果不确定；统一类型是为了让跨包关联无需转换。

---

## DATA-4 pgvector 维度上限（✅ MUST）

- 当向量维度 **> 2000** 时**禁止**使用 `vector` 类型建索引（`ivfflat` 与 `hnsw` 同限），**必须**使用 `halfvec`（上限 4000 维）。
- 当向量维度 **≤ 2000** 时两者皆可，按规模选择索引形态。

**为什么**：`vector` 类型的索引上限是 2000 维，超出时建索引直接失败；这是实测结论，不是偏好。

---

## DATA-5 密文字段禁止宽查询（✅ MUST）

**禁止**对包含加密载荷的表使用 `SELECT *`；**必须**显式列名查询。

**为什么**：一旦有人对结果做序列化或日志输出，密文就会流到不该去的位置；显式列名让"哪些字段可能敏感"在代码里可见。

---

## DATA-6 Session 事件只追加（✅ MUST）

Session 事件表**必须**只追加；**禁止**原地修改或删除已写入的事件。

事件序号连续性**必须**由持久化实现自身断言，**禁止**依赖调用方自觉。

**为什么**：Session 日志是模型可见历史的唯一重建依据；可改写的历史无法用于审计与重放。

---

## DATA-7 软删与硬删语义不得互换（✅ MUST）

需要保留可恢复性的数据**必须**用软删标记；需要彻底移除的数据（如用户拒绝的记忆候选）**必须**硬删。

**禁止**用软删冒充"已删除"来隐藏数据仍存在的事实。

**为什么**：两者对用户是不同承诺；混用会让"删除"失去可信度。
